## 0. The verdict

The corrections of 2026-09-18 mostly hold on the design pages, the register and the brief, but the
documentation is not yet ready to be turned into a script, and the three-day build is not ready to
run. Of the 38 rows fixed on 2026-09-18, 29 hold in full and 9 hold only in the page the row named
while a companion page still carries the defect; none of the six rows the three-day README owes
after that review has reached the day files or the code, and the halt lever is still writable by
the service it halts (X-33), which now also breaks a command, because day 2 and day 3 pull K0
through an endpoint the code removed. Google moved under the design in thirteen days: Vertex AI is
Gemini Enterprise Agent Platform; Agent Gateway and Agent Registry have been GA since 2026-06-18
and the gateway now honours VPC Service Controls; Agent Registry can be named in a deny policy; the
Observability commands left beta in SDK 586.0.0; Security Command Center has a new Standard tier
that can switch itself on in `global`; and Google now documents that a gateway's registrations
must live in the gateway's own project, which contradicts P71's shared registry and is the one
design-level finding of the day (R-11). The design pages lag behind setup files that had
already corrected them (the Workspace identity filter, the SCC paging filter, the SecOps
connection, the `gemini-cmek` rotation). The platform layer is well built for automation — every
step has a `need` line, a VERIFY and a rollback, and the irreversible steps carry gates — but 20
high rows in it stop a script as written: `op-set.sh` cannot read back a project-level policy;
`exists_or_pending` is called with the wrong number of arguments in three files; PAM calls lack a
quota project in six files; Cloud KMS is never enabled where 14 uses it; one `pam grants search`
lacks its required flag; one `bq query` has no project; one `--update-mask` value is invalid; a
checker, a key and two file shapes do not match their producers; and the bootstrap exception is
one role short of what the PAM catalogue needs. Each is a local fix. Once they are made, a
script can run 433 of the 767 platform-layer steps (56 %), must stop at 268 that belong to a
person or the Admin console, and must skip 66 that are BLOCKED; it can request every PAM grant
and wait for it, but it can approve none, sign none and witness none, so it is a guided runner,
not an unattended one. The regulatory frame holds — the Art. 6 guidelines are still draft, no
standard is cited, the Omnibus dates stand, ISA2027 governs TISAX orders from 2027-01-01 — but
three facts moved: EN 18286 is published (not cited); the EU database for Art. 49 registration
will not open before the third quarter of 2027, so Wall-E's Stage 1 cannot carry a registration
id on the calendar the pages show and legal must decide whether Stage 1 waits; and the Art. 72(3)
template became Commission guidance due by 2027-09-02. The derived sets keep every honesty rule
but repeat stale facts: the one-picture diagram says more than the design in seven places,
eight derived pages say the three-day build owes nothing or already carries the full build's
names, six say no price is quoted anywhere, and the brief still says "Vertex AI". None of this is a flaw in the stance; every row is a page to change before
the script is written or the documents are handed on.

## 8. What is sound

A script author and a sponsor may rely on these; each was found right in more than one place on
2026-10-01 and contradicted nowhere.

- **The stance has not moved.** No page loosens a standing constraint: no domain-wide delegation,
  ever; no model holds a credential or produces an approval, a signature, a halt, a veto or a
  refusal; the action service is the only credential holder; a dry run never mutates; humans raise
  autonomy and machines lower it; Mo reaches production only through a merged pull request; P33 is
  designed around and never re-argued. No setup step in the platform layer creates, authorises or
  uses a domain-wide delegation client, and 06 OB-1.4 stops if one belongs to a platform identity.
- **Every command group the platform layer runs exists at the stage the pages state**, and the
  launch-stage questions Google settled since 2026-09-13 settled in the design's favour: Agent
  Gateway and Agent Registry GA on 2026-06-18, Model Armor on the gateway GA on 2026-06-24,
  Unified Access Policies GA on 2026-08-31, VPC Service Controls on the gateway from 2026-09-09.
- **The setup files are built for automation.** Every step has a `need` line or only reads, a
  VERIFY and a rollback; `penv_set` refuses a changed value; `need` refuses empty, *tbd* and
  placeholder values; `sitting_end` fails closed; the irreversible steps carry gate records and
  confirmation lists; 12's two irreversible removals already run inside gate functions; the
  BLOCKED steps match README §8 bar three rows; the order across files is coherent (SCC Premium in
  `eu` before the first location policy, B21 before any module run, fan-out sinks before the
  aggregated sinks, the throwaway lock probe before the production buckets).

  approves a PAM grant, never merges a policy pull request, does not verify their own evidence
  path, and never sees a key; every witness and approver step names the second human; the sandbox
  tenant is kept apart from the platform owner's credentials.

  REST read-back; the Gemini Enterprise host, CMEK call, retention values, feature keys and audit
  classes in setup/19; the gateway chain of setup/20; the Agent Registry flags and limits; the PAM
  surface and limits; the WIF issuers and mappings; Agent Identity on Agent Runtime; the billing
